# Flaky tests

*The known flaky tests, collected 2026-11-22 on main `2ea39e6de`. The sources:*

- *every CI run from 2026-11-04 to 2026-11-22 (1,000 `ci.yml` runs). That is the failed
  jobs of every failed run and of every earlier attempt of a rerun run, plus the
  `FLAKY`/`TRY 1 FAIL` lines (nextest's retry) in 120 green runs;*
- *the cut notes and design docs (`git grep -i flak`);*
- *`.config/nextest.toml`;*
- *the session memory notes.*

*A test counts as flaky only when it failed and then passed at the same head (a rerun, or a
nextest retry), or failed on several unrelated branches without a code change that explains it.
A failure that hit every branch in one window and then stopped was a red main, not a flake; those
are listed apart at the end.*

**Status words.** **FIXED** names the change. **OPEN** says why it was left and what the owner
must decide. **COVERED** means the test is retried once by nextest (a pass on retry is reported
`FLAKY`) and has no root fix yet. **WATCH** means seen once and not reproduced.

*Since doc 51 unit FL.2 (2026-11-23) the retry is a row in
`crates/mush-contract-tests/flaky-known.toml`, not nextest's hand-kept `load-sensitive` list.
Every row here that is OPEN, COVERED or on WATCH has one, with its doc 51 class and an expiry
fourteen days on. A FIXED row has none, except row 5, whose second failure is on watch.
A story run at named phases (doc 51 unit FL.4) is written here by its story's name; its tests
are `<story>::<phase>`.
`docs/flaky-observed.md` is the generated table of what
CI and the soak saw (`scripts/flake_report.py`).*

Run links are `https://github.com/conclavio/rustmush/actions/runs/<id>`; "a1" is attempt 1.

### Notes

- **Row 1, the product side.** The same order can occur in the server's world loop: an owed
  `exit` is queued, and a tick runs `exit::forget` before the write is staged. The stale write is
  then refused in the command-submit drive, and its actor (the pilot whose carrier was lost) is
  sent
  `mush_core::action::SUBMISSION_REFUSED_LINE` for a write they never typed. The world state is
  right: the exit is no longer owed, and the rejoin goes in on the next pass. Making that refusal
  silent needs a "quiet refusal" path for host-owed writes, or a way to withdraw a queued
  submission when `exit::forget` runs. That is a design call for the owner, not this fix.
- **Doc-recorded flakes not seen in the 1,000 runs** (2026-11-04..22). These are the September
  and October entries of the 16b, 16c, 17b, 17g, 18, 20 and 22 cut notes:
