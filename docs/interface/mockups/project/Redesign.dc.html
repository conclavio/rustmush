Turn 1 — two directions

Modernizing the web client

Both directions attack the same four things you called out: the wall of text, no sense of place, unguessable commands, and the dated shell. They disagree about whether the web client should stop looking like a terminal or lean all the way in. Everything is built on the palette already in app.css. Side by side: 1a and 1b.

1a

Scene

The web client stops pretending to be a terminal.

Prose is typeset as prose: a serif at a readable measure, poses grouped under the speaker's name, and everything that isn't the story — system chatter, channels, echoes — demoted to small mono in a cool grey. Warm colour means in-character, cool means out. Newcomers never have to know the word pose: the composer has a mode switch, and every command they could type is behind ⌘K with the real usage line from the command table.

1b

Console

The web client becomes the best terminal you've ever used.

Instead of hiding the terminal, this makes the terminal beautiful: box-drawn panes, gauges, glyph columns, a hotkey strip along the top and a legend along the bottom, in the spirit of rebels-in-the-sky. Everything is mono, nothing is rounded, information density is the point. The payoff is parity almost for free — this layout is the ratatui layout, so the TUI and the web client are recognisably the same game, and a veteran's muscle memory transfers in both directions.

The ratatui TUI

Shared by both directions — this is the parity floor.

Today the TUI is three bordered boxes and a wall of scrollback. Four changes carry most of the weight: a hotkey strip so panes are discoverable without reading docs, a room status line so place is always on screen, a speaker gutter so poses stop running together, and gauges instead of a text prompt. Same 120×34 budget, same OutputEvent stream.

Line mode

Still a scrolling text stream. Just a legible one.

Nothing here needs cursor addressing, so it works on any client back to a 1994 telnet wrapper. The changes are typographic: a rule under the room name so look reads as a heading rather than another sentence, exits on their own labelled line, poses hanging-indented under the speaker so a long pose doesn't merge into the next one, and dice output as one aligned line instead of a paragraph. Colour is unchanged from AnsiTheme::classic.

What changed
Room name is a heading. Name, dbref, rule. The desc is a paragraph under it, not the second half of a run-on line.
Labelled facts. Here / Exits / Weather in a fixed 9-column gutter, so you can scan for the one you want.
Speaker gutter. A 10-column name column with hanging indent. Long poses stay visually one block.
Rolls are one line. Pool, dice, total, difficulty — aligned, so a series of rolls forms a table.
WHO gains Where. The single most-asked question in any MUSH, and the footer answers "is anyone near me".
What the server owes the clients
WhoEntry.location already exists but is unused — populate it and both rails can group by room.
OutputEvent::Composing { actor, active } — the soft-typing indicator. Coalesced, room-scoped, ignorable.
OutputEvent::AgentTurn { npc, state } — the "is thinking" affordance, from the NPC turn the world loop already schedules.
Query "commands.list" — the real command table as a keyframe (name, aliases, usage, module, help topic, power gate). Feeds ⌘K / ^K in all three clients.
RoomView.ambient — zone, IC clock, current weather line, so the header band isn't reconstructed from scrollback.
Scene { id, started, poses } — lets scene mode, the scene log, and the pose counter exist without client-side guessing.
