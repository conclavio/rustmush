### 1. Executive Summary & Current Baseline

At **~1.87M lines of Rust** across **52 crates** (~1.37M lines in `src/` with inline `#[cfg(test)]` modules, ~502k lines in `tests/`, and **10,600+ `#[test]` / `#[tokio::test]` functions**), `rustmush` has one of the most sophisticated self-governing test architectures of any Rust game engine:

- **Self-enforcing architectural & CI tripwires ([`mush-contract-tests`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/Cargo.toml))**: 33 contract binaries enforce panic-surfaceratchets ([`panic_budget.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/tests/panic_budget.rs)), per-crate Clippy restriction lint floors ([`restriction_lints.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/tests/restriction_lints.rs)), toggleable feature compilation ([`feature_matrix_inventory.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/tests/feature_matrix_inventory.rs)), reachability of every `#[ignore]` / `REDIS_URL`-gated test in CI ([`ci_gated_test_inventory.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/tests/ci_gated_test_inventory.rs)), `tacsim` shard completeness ([`ci_tacsim_shards.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/tests/ci_tacsim_shards.rs)), deterministic RNG routing ([`provider_rng_policy.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/tests/provider_rng_policy.rs)), and projection redaction ([`projection_json_leaks`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/src/lib.rs#L64-L70)).
- **Coalesced integration binaries & Nextest (Cuts T.0–T.3)**: Coalescing 373+ separate integration binaries (each linking 300–730 MB of engine code) into grouped roots ([`shard_1.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/tacsim/tests/shard_1.rs)..`shard_10.rs` in `tacsim`, [`split_boundary.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-server/tests/split_boundary.rs) / `commerce_composition.rs` / `world_task.rs` in `mush-server`, [`durable_process.rs`](file:///c:/Users/faeni/antigravity/rustmush/crates/mushd/tests/durable_process.rs) / `world_journeys.rs` / `sim_lenses.rs` in `mushd`, and `split_halves.rs` in `mush-gateway`) paired with [`.config/nextest.toml`](file:///c:/Users/faeni/antigravity/rustmush/.config/nextest.toml) and the warm-target VPS gate ([`gate.yml`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/gate.yml)) solved the immediate linker/disk cliff.

However, the test pyramid has become **heavily inverted**. Because adding full-composition story tests and source-scanning tripwires has been the primary way every cut proves completion, **summed integration test time in `tacsim` (~410 test-minutes) and `mush-server` (~105 test-minutes) is scaling faster than the codebase**, while critical lower-level seams, client surfaces, and property/fuzz boundaries remain under-covered.

### 3. Where We Overtest

#### A. Duplicate CI Jobs Recompiling and Re-running the Exact Same Tests
Every push/PR runs the 20-cell `test` matrix ([`ci.yml`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L517-L760)), where:
- `test (rest-libs)` runs `cargo nextest run -P ci --workspace --exclude mush-bot --exclude tacsim --exclude mushd --exclude mush-server --exclude mush-gateway` (plus `mush-proto --features ts` and `mush-testkit --features toy-ruleset`).
- `test (rest-server)` and `test (rest-server-boundary)` run all of `mush-server` (`commerce_composition`, `world_task`, `split_boundary`, `--lib`, `--bins`, `--doc`).
- `test (rest-gateway)` and `test (rest-mushd)` run all of `mush-gateway` and `mushd`.

Yet [`ci.yml`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml) **also** spins up **5 separate Ubuntu jobs on every push and PR** that check out the repo, restore cache, compile, and re-execute non-ignored tests that `rest-libs`, `rest-server`, `rest-server-boundary`, and `rest-gateway` already ran:
1. [`provisioning`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L842-L855): Recompiles `mush-server` to run `--test split_boundary provisioning_smoke::`, which already runs inside `test (rest-server-boundary)`.
2. [`kernel-contracts`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L857-L886): Recompiles and re-runs `mush-contract-tests` (`--lib`, `gate5_fault_matrix`, `schedule_source`, `ci_gated_test_inventory`, `panic_budget`, `restriction_lints`) and `mush-industry --test e7c4`—every single one of which already ran in `test (rest-libs)`.
3. [`definition-wire-fixtures`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L1266-L1301): Spins up a runner to re-run 9 `--exact` tests in `mush-core`, `mush-contract-tests`, and `mush-proto --features ts --test ts_export`—all of which already ran in `test (rest-libs)`.
4. [`direct-rand-policy`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L1303-L1321): Spins up a runner just to run `cargo test -p mush-contract-tests --test provider_rng_policy` (already run in `test (rest-libs)`).
5. [`truth-serialization-policy`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L1323-L1346): Spins up a runner to re-run `truth_serialization_policy` plus 6 `--exact` tests across `mush-core`, `mush-contract-tests`, `mush-server`, `mush-gateway`, and `mush-net-ssh`—forcing that single job to compile the entire server, gateway, and SSH stack just to re-run 7 tests that already ran in `rest-libs`, `rest-server-boundary`, and `rest-gateway`!

*(Even inside [`redis-faults`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L888-L900), lines 895–897 run unfiltered `authoritative_boot::`, `authoritative_process_kill::`, and `persistence::`, which re-runs all non-Redis tests in those modules alongside the `REDIS_URL`-gated ones.)*

#### B. Full-Composition & Real-Clock "Story" Tests Used for Combinatorial Domain Logic
- **34-crate world boots per test**: `tacsim` has **1,719 integration tests** across 135 files in `tests/shard_1..10` (266,917 lines of test code, ~410 summed test-minutes), and `mush-server` has **306 integration tests** (41,156 lines, ~105 summed test-minutes). Many of these tests boot the entire 34-crate composition root (`compose_server_modules` / `TestWorld`), hydrate starter packs or geology sites, and run multi-step tick loops to verify narrow domain edge cases (e.g., individual refusal messages, UI string formatting, or single-formula variations) that could be tested 100x faster against narrow module fixtures or unit tests.
- **Debug-mode CPU simulation loops**: In [`ci.yml`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L1028-L1184), M7 (`mind-commerce-acceptance`, 6 matrix cells) and M8 (`m8-gate-stories`, 3 matrix cells) run full arena + Rhai + physics + Registry maintenance loops in **unoptimized debug builds** (`opt-level = 0`), where rating a single certificate requires ~1,070 maintenance cycles (~8,500 full simulation steps) and takes 30–180 minutes per cell.
- **Wall-clock sleeps & polling loops**: Across `mushd`, `mush-gateway`, `mush-server`, and `mush-bot`, dozens of tests spawn real OS child processes and poll with `tokio::time::sleep` / `std::thread::sleep` over real 250ms arena pulses or 1s/5s server ticks (as analyzed in [`docs/testing-rate.md`](file:///c:/Users/faeni/antigravity/rustmush/docs/testing-rate.md)). This is why [`.config/nextest.toml`](file:///c:/Users/faeni/antigravity/rustmush/.config/nextest.toml#L40-L89) has had to accumulate **23 separate `load-sensitive` binary/test filters** with `max-threads = 2` and `retries = 1` (and [`37-ic-phase-closeout`](file:///c:/Users/faeni/antigravity/rustmush/docs/design/37-ic-phase-closeout-2026-11-02.md#L106-L108) notes `f6` still flaked under 32-core load).

### 4. Structural Testing Changes to Consider as the Codebase Grows

As the repository grows past 2M LoC, the current pattern of manually rebalancing `shard_1..10` and adding more matrix cells in [`ci.yml`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml) will hit diminishing returns (each new shard still pays ~7–9 minutes of compilation/link overhead). Consider these 7 structural changes:

#### 1. Compile Compute-Heavy Dependencies with `opt-level = 2` in Dev/Test Profiles
Right now, `cargo nextest` compiles all workspace crates and dependencies at `opt-level = 0`. CPU-bound inner loops—Rhai script evaluation (`rhai`), software raycasting/rendering (`mush-pixel`), geology/hydrology generation (`mush-atlas`), cryptographic hashing (`sha2`, `blake3`), and serialization (`serde_json`, `rmp-serde`)—run **5–15x slower** at `opt-level = 0`.
- **Change**: Add `[profile.dev.package.<pkg>] opt-level = 2` in the root [`Cargo.toml`](file:///c:/Users/faeni/antigravity/rustmush/Cargo.toml#L150-L162) for hot third-party dependencies (`rhai`, `sha2`, `serde_json`, `rmp-serde`, `flate2`, `image`) and leaf compute crates (`mush-pixel`, `mush-dice`).
- **Impact**: Dramatically cuts runtime of `tacsim` shards, `mush-bot`, and M7/M8 acceptance suites without slowing down incremental builds of high-level crates (`tacsim`, `mush-server`).

#### 2. Collapse Redundant Standalone CI Jobs into Existing Matrix Cells
- **Change**: Fold [`kernel-contracts`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L857-L886), [`definition-wire-fixtures`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L1266-L1301), [`direct-rand-policy`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L1303-L1321), [`truth-serialization-policy`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L1323-L1346), and [`provisioning`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml#L842-L855) into `test (rest-libs)` and `test (rest-server-boundary)` (which already compile and run 100% of those tests!). If distinct GitHub check names or log groups are desired for K8 auditability, emit `::group::` markers or inspect the JUnit XML generated by `rest-libs` / `rest-server-boundary` rather than spinning up 5 extra Ubuntu runners that recompile `mush-server` and `mush-contract-tests` from scratch.
- Also coalesce `mush-contract-tests`'s 33 separate integration binaries into 2–3 group binaries (`policy_scans`, `kernel_contracts`, `composition_contracts`) just as Cut T.3 did for `tacsim` and `mush-server`.

#### 3. Replace Manual `shard_1..10` File Shuffling with Domain-Grouped Binaries + Nextest Partitioning
Moving files between `crates/tacsim/tests/shard_1/`..`shard_10/` by hand whenever shard runtimes drift (already bumped from 4 → 6 → 10 shards in one week) creates git-blame churn, forces duplicate `#[path = "support/..."]` boilerplate in every `shard_N.rs`, and breaks path-keyed allowlists.
- **Change**: Group `tacsim/tests/` into **stable domain binaries** (e.g., `arena_sim.rs`, `field_combat.rs`, `space_orbital.rs`, `industrial_commerce.rs`, `detachment_ops.rs`) so each binary only needs its own support modules, and either:
  - Run each domain binary in its own CI shard (using `cargo nextest run --partition hash:1/2` if a single domain binary grows past 15 minutes), **or**
  - On [`gate.yml`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/gate.yml) / self-hosted runners, build once and run all tests in one pool.
- In [`state-slot-owners.toml`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/state-slot-owners.toml), key test exemptions by module basename or forbid new `module_state_mut` exemptions in `tests/` altogether (see #5 below).

#### 4. Eliminate Real Wall-Clock Sleeps in In-Process Tests (`tokio::time::pause` + `TestWorld` Clock)
As documented in [`docs/testing-rate.md`](file:///c:/Users/faeni/antigravity/rustmush/docs/testing-rate.md), tests that use real wall-clock sleeps (`tokio::time::sleep` over 250ms arena pulses or 1s/5s server ticks) both waste CI minutes and cause CPU-starvation flakes requiring [`.config/nextest.toml`](file:///c:/Users/faeni/antigravity/rustmush/.config/nextest.toml#L40-L89)'s 23-entry `load-sensitive` retry list.
- **Change**: Standardize in-process async tests in `mush-server` (`world_task`, `split_boundary`, `commerce_composition`) and `mushd` (`sim_lenses`, `world_journeys`) on deterministic virtual time (`#[tokio::test(start_paused = true)]` + manual tick/pulse advancement), reserving real wall-clock timers strictly for the handful of cross-process `kill -9` / SIGTERM tests in `durable_process` and `split_halves`.

#### 5. Enforce "No Fiat State Mutation" in Integration Story Suites & Shift Combinatorial Testing Left
- **Change**: Generalize [`tacsim_integration_tests_never_mutate_space_bubble_book_directly`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/tests/arena_library.rs#L940-L965) so that **no new integration test** under `crates/tacsim/tests/` or `crates/mush-server/tests/` may call `module_state_mut` or `unchecked_module_state_mut` directly—ratcheting the test section of [`state-slot-owners.toml`](file:///c:/Users/faeni/antigravity/rustmush/crates/mush-contract-tests/state-slot-owners.toml) downward just like `panic_budget.rs`.
- Provide ergonomic **command-driven test builders** in `mush-testkit` (e.g., `TestWorld::exec_ok(actor, "...")`) for integration stories, while moving combinatorial branch/refusal testing down into fast unit tests inside the owning domain crate (`mush-economy`, `mush-industry`, `mush-tactics`, `tacsim/src/`).

#### 6. Add Property-Based (`proptest`) Suites to All Wire, Persistence, and Sandbox Boundaries
- Add dedicated `tests/*_proptest.rs` suites (which run in seconds inside `rest-libs`) for:
  1. `mush-ipc`: arbitrary byte stream framing, version mismatch negotiation, and round-trip serialization for every `GatewayToServer` / `ServerToGateway` variant.
  2. `mush-sshdoorway-proto`: arbitrary frame decoding and round-trip properties.
  3. `mush-mind`: generative Rhai AST / JSON memory round-trip, canonical hash stability, NaN/Inf rejection, and op/memory budget enforcement.
  4. `mush-pixel` & `mush-content`: corruption-resilience (never-panic) tests on `.mupk`, RLE, SIXEL, Kitty, and pack binary decoders.
  5. `mush-economy`: stateful `proptest` state-machine test verifying double-entry sum conservation and checkpoint/replay identity.

#### 7. Close the Client, Release-Guard, and Nightly/Dispatch Governance Blind Spots
- **Android CI**: Either add a lightweight `android` job to [`ci.yml`](file:///c:/Users/faeni/antigravity/rustmush/.github/workflows/ci.yml) (`./gradlew testDebugUnitTest compileDebugAndroidTestKotlin lintDebug`, gated by `paths: ['android/**']`) and fix the stale `"Dropzone Alpha — Forward Pad"` assertion in [`MainScreenTest.kt`](file:///c:/Users/faeni/antigravity/rustmush/android/app/src/androidTest/kotlin/io/conclavio/rustmush/ui/main/MainScreenTest.kt#L25), or explicitly archive `android/` if it is an inactive prototype.
