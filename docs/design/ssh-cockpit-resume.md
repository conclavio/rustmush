# SSH cockpit resume

An opted-in SSH client can ask the instance gateway to recover one disconnected pane. The instance owns the ticket and the character session. A doorway forwards the ordinary game channel and a second SSH subsystem channel to the same instance. A new doorway generation can forward the request.

## Wire version 1

Before requesting a shell, the client sends the SSH environment request `RUSTMUSH_RESUME_V1` with value `issue:<pane>` or `redeem:<pane>`. The pane identifier is a random, non-secret string of 32 lowercase hexadecimal digits. On the same authenticated SSH connection the client opens a session channel and requests the `rustmush-resume-v1` subsystem. Keeping credentials on this channel lets the terminal record the game without recording a resume ticket.

Each frame starts with a four-byte unsigned big-endian payload length followed by at most 1024 bytes of UTF-8 JSON. The mode and pane in the request must agree with the shell request. Account and character are established through the normal gateway authentication and character ownership checks.

| Direction | Payload |
| --- | --- |
| Client requests a ticket | `{"v":1,"op":"issue","pane":"<pane>"}` |
| Client requests recovery | `{"v":1,"op":"redeem","pane":"<pane>","ticket":"<ticket>"}` |
| Gateway needs an in-game login | `{"v":1,"status":"auth_required"}` |
| Gateway confirms attachment | `{"v":1,"status":"issued","ticket":"<ticket>","grace_seconds":300}` or the same shape with `"status":"redeemed"` |
| Gateway ends an unsuccessful request | `{"v":1,"status":"expired"}`, `denied`, `unavailable` or `busy` |

Each ticket encodes 32 random server-generated bytes in unpadded base64url. The gateway retains a digest and the authenticated account, character, pane, previous connection and exact session incarnation. Link loss starts the grace clock. A clean quit revokes the ticket. The client can hold a ticket only for its current pane and verified destination. Closing the client or restarting the instance gateway ends that form of recovery.

Redemption reserves the ticket while the gateway checks the linkdead session and current world admission. A successful recovery rotates the ticket. A failed or cancelled reservation can be retried within its original grace. The session manager and game retain authority over grace expiry, seat ownership and any later `BOARD` request. Reopening a cockpit uses the current PTY size and a fresh view. Past keypresses, sounds and clipboard operations are excluded from recovery.
