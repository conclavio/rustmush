### 3.1 Cut H1 — the module store-read seam

**What it is.** A module reaches the store two ways today: boot (`ModuleBootData.kv` from `module_json_list`) and blind writes. H1 adds the third — a bounded, off-loop, per-key read during play with a typed completion — in exactly the shape of the LLM re-entry (treaty ruling 3): snapshot the request synchronously, run the read detached, re-enter as a typed command that a registered handler applies with a full `Ctx`.

**The seam** (all additive, `mush-core`):

```rust
// engine.rs — `Effect` stays `Eq`, so the request carries plain strings
Effect::StoreRead { module: SmolStr, actor: ObjId, correlation: u64, keys: Vec<SmolStr> }   // ≤ MAX_STORE_READ_KEYS; ns is the module's own
WorldCommand::StoreReadDone { module: SmolStr, actor: ObjId, correlation: u64, payload: String }
//   payload: {"docs":[[key,value],…],"absent":[key,…]} | {"failed":"…"} | {"oversized":bytes}, ≤ MAX_STORE_READ_BYTES

// module.rs
pub enum StoreReadResult { Docs { docs: Vec<(SmolStr, serde_json::Value)>, absent: Vec<SmolStr> }, Failed(String), Oversized { bytes: usize } }
pub trait StoreReadCompletion: Send + Sync { fn on_read(&self, ctx: &mut Ctx<'_>, correlation: u64, result: StoreReadResult); }
impl Ctx<'_> { pub fn read_store(&mut self, keys: Vec<SmolStr>) -> Result<u64, StoreReadError>; }   // allocates the correlation; refuses > MAX_STORE_READ_KEYS, an empty key, or a `log:` key outside this module's namespace
Registrar::store_read_completion(handler)   // one per module, exactly like async_completion
```

`Engine` routes `StoreReadDone` beside `ModuleAsyncDone` (`module::apply_store_read_completion`, the same disjoint-borrow shape, the same "unregistered module → warn and drop"). The world task's `spawn_effect_list` gains a `store: &Arc<dyn ObjectStore>` parameter, threaded through `release_classified_effects`'s seven call sites, and a `StoreRead` arm: `tokio::spawn` a bounded loop of `module_json_get(ns, key)` — never `module_json_list` — collecting docs and counting bytes, then re-enter with the payload, `Oversized` (nothing else returned) or `Failed`; `STORE_READ_TIMEOUT_MS` bounds the whole loop. **A read is namespace-locked** (D-H-1): `ns` is `ctx.module`, never a parameter, so no module can read another's documents. Reads are effects, released under the existing `ExternalEffect` admission (refused while Booting/Recovering — when no command could have issued one); completions re-enter under `AsyncApply`, and a completion refused by mode, or arriving for an actor that no longer exists, is dropped with a `warn!` and never retried (D-H-3). The store trait's "never during play" doc sentence is rewritten to name this seam and its bounds.

**The ledger cold reader** (`ledger.rs`): `pub fn read_cold_range(docs: &[(SmolStr, Value)], log_id: &str) -> Result<Vec<LedgerEntry>, LedgerReadError>` decodes the returned `log:{id}:{chunk}` docs as `LedgerChunk`s, requires contiguous chunk indices and gap-free `seq`, refuses an unsealed chunk that is not the highest returned (a page may end at the open tail), and orders entries by `seq`. **The page unit is the chunk index** (D-H-2): a reader asks for `[chunk_lo, chunk_hi]` and builds keys with `chunk_key`; no seq→chunk index document is added. A live log's bound is `Ledger::open_chunk(log_id)`; a closed log records its bound on its owner.

**Scenes.** `SceneRecord` gains `log_chunks: Option<u64>` (serde default), stamped from `events.open_chunk(&id)` on the close path (`+timestop/end`); an old record without it pages forward from chunk 0. `+timestop/log` and `+recap` gain `/archive [page]`: for a Closed scene, or a live one whose tail rolled over, the command issues `ctx.read_store(keys for one page)` and returns; `ScenesReadCompletion::on_read` renders the page to `ctx.actor` through the **same** `render_event` and `recap_line` functions the live path uses (one renderer per view), with the personal-recap witness filter applied identically. One read in flight per actor (`MAX_PENDING_STORE_READS_PER_ACTOR` 1; a second `/archive` while one is pending is refused with a line). A page that fails `read_cold_range` reports the breach and renders nothing. The "not yet built" sentences in `timestop_log`, `scene_recap` and `docs/help/timestop.md` retire.

**Canon.** `+chronicle/archive [page]` and `@canon/archive [page]` page the single canon log by chunk, newest page first, through `CanonReadCompletion`, with the scope filter the live `recent()` render uses and retcon marking computed over the returned page plus the RAM tail. `records_for_source`'s window is unchanged (DL-09's documented limit stays E's call). `docs/help/chronicle.md`'s "archive, arriving with the recap tools" retires.

### 3.2 Cut H2 — the K7 production NPC cutover

**What it is.** K7.0–K7.5 closed the kernel and proved it against harness modules; production still boots through `spawn_persist_with_gateway` with no decision runtime, no provider registry and no composed source, so `DEFAULT_DECISION_PROVIDER_WORKERS` is inert (08j §7 "Accept"). #### H2a — the production decision composition

**The provider adapter** (`crates/mush-server/src/decision_llm.rs`, new). `LlmDecisionProvider { owner: OwnerId, llm: Arc<LlmService>, feature: LlmFeature }` implements `DecisionProviderAdapter`. `decide(lease)`: read `lease.prompt()`; build one `ToolDef` per `ProjectedLegalAction` from `presentation().verb/label/help` and `parameters()` — `Boolean` → boolean, `Integer { minimum, maximum }` → integer with bounds, `Text { maximum_bytes }` → string with `maxLength`, `Choice { choices }` → enum; a `Choices` target schema → an enum of the opaque `PerceivedRef` tokens; the system prompt is a fixed frame plus `context.value` fenced as untrusted data (the delimiting `mush-npc::prompt` already uses); one `CompletionRequest` with forced tool choice and a bounded `max_tokens`; exactly one `ToolUse` → `DecisionResponse { token: lease.prompt().token, offer, targets, parameters }`; anything else → `Malformed`; a budget trip, a kill switch or a transport error → `Unavailable`; a refusal → `Permanent`. ## 4. Build discipline

10b §4's rhythm per cut: (1) confirm the slice against the tree **by symbol**; (2) build, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo fmt --all --check`; (3) a probe-confirming adversarial verify with the cut's lenses before the next cut builds on it; (4) fold every confirmed finding with a regression test named `vf_<lens><n>_…`; (5) commit with the verify outcome in the message; **push only on the owner's word**. Added for H:

- Every new `_redis_gated` test is named in `ci.yml` **and** the census in `ci_gated_test_inventory.rs` is bumped, in the same commit (the inventory test enforces the first; the second is the pin).
- Every new handler lands on `legacy-handlers.toml` in the same commit. H1's `/archive` switches ride existing verbs; H2's definitions are not verbs; H adds no verb, so the allowlist does not move.
- Every new metric series is aggregate-only and gets a leak probe in the cut that adds it.
- H2a, H2b and H2c are three commits, each independently green (the K side's per-slice rule, applied).
- A cut that touches `engine.rs`, `module.rs` or `world_task.rs` lands that touch as its own small commit and rebases on E7's last commit the same day (§5).

Standing rules: clients render, they never compute (I plan rule 1) — H1's archive pages carry rendered lines, not raw chunks; one internal view feeds every projection — the archive uses the live renderer; whole where it can be, bounded always; additive wire evolution — H adds no proto type; no new idle-stamping path — a read completion never touches `last_input`.

## 6. Decisions

- **D-H-1** The store-read seam is an `Effect`/`WorldCommand` pair routed by module name, namespace-locked to the requester, never a store handle on `Ctx`. Rationale: treaty ruling 3; `Ctx` stays sync; `mush-core` never holds the store; a module reading another's documents is the leak the namespace rule exists to prevent.
- **D-H-2** Cold ledger reads page by **chunk index**, never by `seq`; no seq→chunk index document is added; a closed scene records `log_chunks` at close. Rationale: no ledger persistence-format change; `chunk_key` already names the page.
- **D-H-3** A read completion that cannot be applied (mode refusal, actor gone, oversized, failed) is dropped with a log; the requester sees nothing and may ask again; the engine never retries a read. Rationale: reads are views; retry machinery for views is how loops wedge.
- **D-H-4** One production LLM decision provider, parameterised by owner; E7's owners reuse it. Rationale: the adapter is the security-sensitive half (09 K7.2); two copies are two audit surfaces.
- **D-H-5** With the LLM disabled the provider still composes and answers `Unavailable`; the kernel's fallback selects `npc_idle`. Rationale: `spawn_persist_with_gateway_and_decisions` refuses a source without a provider; a keyless clone must boot (README's rule).
- **D-H-6** Capture is a **selector** (`Ctx::capture_decision`), expanded by the driver with the engine's projection, admission and key ring; modules never construct plans or hold keys. Rationale: E7c2 B1's rule applied to decisions; K7.2's truth boundary.
- **D-H-7** NPC dialogue stays on the legacy `ModuleAsync` lane in H; only mechanical decisions and mechanical abilities move. Rationale: 09's audit table ("keep … for non-mechanical legacy dialogue during migration"); `ops.md` lists an in-flight LLM call as an accepted loss.
- **D-H-8** The scale harness reports; it fails only under `SCALE_ASSERT=1`. Rationale: numbers first, thresholds once the owner has seen numbers (08g §12.1 item 5 is a decision, not a gate).
- **D-H-9** `encoded_len` is stashed at bundle construction, `#[serde(skip)]`, never hashed. Rationale: no second serialization on the commit path (lens O).
- **D-H-10** `EconomicCause::Command.serial` is the per-boot correlation, documented as such; no core change. Rationale: a durable dispatch id does not exist and would be a K item.
- **D-H-11** H2b's trigger is the scene turn; the tick's free-running dialogue never captures a decision. Rationale: the design doc's "NPCs act only when given their scene turn token"; the smallest trigger that exercises every kernel transition in production.

## 10. Review outcome (Draft 0.1 → 0.2)

The review re-opened every symbol the draft leaned on that had not been opened while drafting, with the brief "find the claim the tree contradicts". Eight findings changed the body; seven claims were re-confirmed; the owner keeps the ★ questions.

### 10.1 What was wrong and is now changed

1. **`DecisionCaptureDraft` had no `actor`.** The draft let `capture_decision` take `ctx.actor`, but `WorldObserver::on_event` runs with the event's trigger as `ctx.actor` (the facilitator who typed `+timestop/next`) and `TickHandler::tick` runs with `#1`; H2b captures from an observer, so the decision would have been captured *for the facilitator*. Fixed: `actor: ObjId` on the draft, the driver projects for it, and the `npc` capture provider refuses any actor that is not an `ObjKind::Npc` with a profile. H2c is unaffected: `AsyncCompletion::on_complete` runs with `ctx.actor` = the NPC (`defer_turn` sets `actor: npc` on the effect), so `submit_authoritative`'s `self.actor` is right there.
2. **`[npc]` does not exist.** `mush-config`'s `Config` has no npc section; `NpcConfig` lives in `mush-npc/src/runtime.rs` and is only ever `Default`. `[llm]` is an untyped `toml::Value` parsed by `mush_llm::config::LlmConfig`. Fixed: `NpcCfg` is a new section (the `TacsimCfg` pattern), and `decision_workers` is parsed by `mush-llm`'s config, not `mush-config`'s.
3. **`LlmFeature` is a closed enum** with `route_key()`; "a new `[llm.routes]` key" was not a thing one could add. Fixed: `LlmFeature::NpcDecision` is a `mush-llm` variant with route key `npc_decision`; an absent route is `LlmError::InvalidRequest`, which the adapter classes `Unavailable`, and boot warns once.
4. **Hold time measured around the call would count reserve back-off.** `commit_authoritative_with_retry` retries a transient `reserve_authoritative_intent` with exponential delay before the slot is held. Fixed: the function gains `&Metrics` and starts the clock at the exact reservation receipt.
5. **`release_classified_effects` has seven call sites**, not eight — the count included the definition.
6. **`DecisionCause` is `{ kind, instance, replaceable_key }`.** The draft's "keyed on `(scene, round, actor)` and marked replaceable" is now stated in those fields: `instance` over `(scene, round, actor)`, `replaceable_key` over `(scene, actor)`, which is precisely K7.1's explicit-cause coalescing and keeps a scene's NPC at one non-terminal record.
7. **Redis logical dbs are mostly taken.** `persistence.rs` uses 7–11, 14 and 15, `m10c_e2e` uses 6, and `durability_e2e` uses 12 and 13 (H1's build found this last pair; Draft 0.2 had assigned them to H4). The H4 tests take 3 and 4; H1's took 5; H3's two take 1 and 2; the README range widens from 7–15 to 1–15 across the cuts.
8. **`Settled::Posted`'s payload carries `#[allow(dead_code)]`** — T6's "unread payload" is exactly that allow; the fix removes it with the read.

### 10.2 What the review confirmed sound

- `Effect` and `WorldCommand` both derive `Eq`, so string payloads are forced, and the `ModuleAsyncDone` routing (`apply_async_completion_with_action_state`, warn-and-drop for an unregistered module) is the shape to copy for `StoreReadDone`.
- `SceneRecord` derives `Serialize`/`Deserialize` without `deny_unknown_fields`, so `log_chunks` with a serde default is additive for old documents; `AuthoritativeBundle` derives `Serialize` only, so a `#[serde(skip)]` length never reaches the wire.
- **No production capture path exists.** `arm_decision_capture` (world_task tests), `DecisionCaptureModule` (gate5 fault matrix) and `tactical_gate.rs` all build the plan outside the provider through `Engine::project_decision_offers` and a `Mutex`, and production `lib.rs` spawns through `spawn_persist_with_gateway`, never `_and_decisions`. H2a's premise — the kernel is closed, the composition is missing — holds exactly.
- `Engine::discover_decision_dispatches` takes `&self`, so `npc_counts(&Engine)` can read the non-terminal count from a page's admission index without a world borrow.
- `EscalationKind::label` is an exhaustive `match`, so the three new kinds are compiler-enforced everywhere the kind renders.
- The K8.4 `willpower_roll` parameter schema (`pool`, `difficulty`, `ignore_wounds`, `modifier`, `specialty`) covers every `wod_roll` tool input except `willpower` itself, which is the action's own meaning, so H2c's mapping is total for the Willpower case and undefined for the rest — the residual probe is the right instrument.
- `crates/mushd/tests/load_soak.rs` is a session and socket soak; PLAN.md's write-through pipeline soak is genuinely unbuilt, and H3's `scale_authoritative_soak_*` is it.

### 10.3 What is left for the owner

§8's ★ items — q1 (page size), q2 (`+recap/archive` now), q3 (migrate the pool roll, or pin the residual), q5 (the scene-turn deadline), q7 (a tiny-scale run per push) — and one sequencing choice this plan does not make: **whether H2's three sessions run now or when E7 cut 9 lands.** H1, H3 and H4 are five sessions of disjoint work and are the recommendation either way; H2a is what un-gates cut 10's LLM rows, which the E7 order reaches after cut 9, so it can start any time before then without moving E7.
